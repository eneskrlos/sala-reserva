# Memory.md — Memoria del proyecto

> Decisiones, modelo de datos y aprendizajes que deben persistir entre sesiones.
> Última actualización: 2026-11-24.

## Contexto
- Proyecto greenfield. Repo en GitHub: `git@github.com:eneskrlos/sala-reserva.git`.
- Flujo **git-flow**: `main` (producción), `develop` (integración), features/tasks.
- Rama de análisis/spec: `feature/analyse_project`.
- Entorno: JDK 21 instalado (target Java 17), Maven 3.9.12, Docker 29, git + git-flow.

## Decisiones de arquitectura
- **Monolito Modular**, paquete base `com.reuniones.salareserva`.
- Módulos: `auth`, `salas`, `reservas`, `shared` (config, exception, dto comunes).
- Capas por módulo: Controller → Service → Repository (Spring Data JPA) + entidad + DTOs/mapper.

## Decisiones de negocio
- **responsable**: texto libre (nombre/email) en el body de la reserva.
- **Cancelar reserva**: borrado lógico → `estado = CANCELADA`. No bloquea horario.
- **Estados de reserva**: `ACTIVA`, `CANCELADA`.
- **Solape (HTTP 409)**: misma sala y estado `ACTIVA` con
  `inicio < fin_existente AND fin > inicio_existente`.
- **Auth**: usuarios en BD (semilla con BCrypt). Endpoints `login` y `register` públicos.
  GET públicos; POST/DELETE requieren JWT.

## Modelo de datos (detalle)
### usuarios
| Columna | Tipo | Notas |
|---|---|---|
| id | BIGSERIAL | PK |
| username | VARCHAR | UNIQUE, NOT NULL |
| password | VARCHAR | NOT NULL (hash BCrypt) |
| rol | VARCHAR | NOT NULL, DEFAULT 'USER' |
| created_at | TIMESTAMPTZ | DEFAULT now() |

### salas
| Columna | Tipo | Notas |
|---|---|---|
| id | BIGSERIAL | PK |
| nombre | VARCHAR | UNIQUE, NOT NULL |
| ubicacion | VARCHAR | NULL |
| capacidad | INT | NULL, CHECK (capacidad > 0) |
| activa | BOOLEAN | NOT NULL, DEFAULT true |
| created_at | TIMESTAMPTZ | DEFAULT now() |

### reservas
| Columna | Tipo | Notas |
|---|---|---|
| id | BIGSERIAL | PK |
| sala_id | BIGINT | FK → salas(id), NOT NULL |
| responsable | VARCHAR | NOT NULL |
| inicio | TIMESTAMPTZ | NOT NULL |
| fin | TIMESTAMPTZ | NOT NULL |
| estado | VARCHAR | NOT NULL, DEFAULT 'ACTIVA' |
| created_at | TIMESTAMPTZ | DEFAULT now() |

Constraints de `reservas`:
- `CHECK (fin > inicio)`.
- *Exclusion constraint* (requiere extensión `btree_gist`):
  `EXCLUDE USING gist (sala_id WITH =, tstzrange(inicio, fin) WITH &&) WHERE (estado = 'ACTIVA')`.
- Índice por `(sala_id, inicio, fin)` para consultas/filtros.

## Patrones de diseño previstos
Repository, DTO + Mapper, Specification (filtros dinámicos de reservas), Global Exception
Handler (ProblemDetail RFC-7807), Builder, Dependency Injection, Filter Chain (JWT).

## Aprendizajes / notas técnicas
- **Versiones**: Spring Boot 3.3.5, springdoc-openapi 2.6.0, Lombok. Java compilado con
  `maven.compiler.release=17` sobre JDK 21.
- **Puerto Postgres (host)**: **5439** (no 5432/5437, ya ocupados por otras instancias Docker
  del equipo: `labgarcias_db_app` usa 5437). Contenedor `sala-reserva-db` atado a `127.0.0.1`.
- **Config datasource** por variables de entorno con defaults locales (`DB_URL`, `DB_USER`,
  `DB_PASSWORD`, `SERVER_PORT`) en `application.yml`.
- **Flyway** gobierna el esquema (`spring.jpa.hibernate.ddl-auto=validate`). Las migraciones
  viven en `src/main/resources/db/migration` (se crean en Task 2).
- **Orden de dependencias**: seguridad/JWT se añaden en Task 3 (no antes, para que Swagger sea
  accesible durante el bootstrap); Testcontainers en Task 6.
- **Swagger UI**: `http://localhost:8080/swagger-ui.html`; OpenAPI JSON en `/v3/api-docs`.
- **Migraciones Flyway** (Task 2): `V1__init.sql` (esquema + `btree_gist` + exclusion constraint
  `excl_reservas_solape`) y `V2__seed.sql`. IDs con `GENERATED BY DEFAULT AS IDENTITY`.
  El rango `tstzrange(inicio, fin)` usa `[)`: reservas contiguas (fin == inicio) NO solapan.
- **Usuario semilla**: `admin` / `admin123` (rol `ADMIN`). Hash BCrypt `$2a$10$` almacenado en
  `V2__seed.sql`. Útil para login/README. En V2 **no** se siembran salas (para no acoplar los
  tests); las salas de demo se crean vía API.
- **Seguridad JWT** (Task 3): jjwt 0.12.6 (API nueva `Jwts.builder().signWith(key)` y
  `Jwts.parser().verifyWith(key)`). Secreto en `app.jwt.secret` (env `JWT_SECRET`), expiración
  `app.jwt.expiration-ms` (default 1h). Token firma HS384/HS256 según tamaño de clave.
  `register` crea usuarios con rol `USER`; login usa `AuthenticationManager` + `UsuarioDetailsService`.
- **Rutas públicas**: `/api/auth/**`, Swagger/OpenAPI, GET de `/api/salas/**` y `/api/reservas/**`,
  y **`/error`**. `/error` es necesario en la lista: ante un 404, Spring reenvía a `/error` y
  `OncePerRequestFilter` no corre en el *error dispatch* (`shouldNotFilterErrorDispatch`), por lo
  que sin permitir `/error` un 404 público se convertiría en 401.
- **Errores**: `GlobalExceptionHandler` (`@RestControllerAdvice`) devuelve `ProblemDetail`
  (400 validación con mapa `errores`, 409 duplicado, 401 credenciales). 401/403 de la capa de
  seguridad (filtros) se emiten como JSON desde `SecurityConfig` (entryPoint/accessDeniedHandler).
